Chameleon Ultra FSK self-trim (experiment)

Test firmware that lets the CU match its emulated HID Prox, Paradox and ioProx cards to a reader's clock, and this page to set it up and read back what it learned. For trying at a real reader, where there's no way to measure the read rate: compare the same card with and without self-trim by switching slots.

Before you start

  • Chrome or Edge on a desktop (Web Serial), with the CU on USB.
  • Chameleon Ultra only, not Lite. Close anything else using the CU's port (ChameLab, the Python CLI).
  • This is experimental firmware. It's based on the Paradox pull request (Paradox read, emulation and cloning), plus the self-trim research, plus fixes for answering a reader that wakes the CU. Flash stock back when you're done.

Test firmware: (source, branch exp/fsk-selftrim-paradox). Flashing replaces the firmware; slots and saved cards are kept. Stock v2.3.0 has no Paradox support: a Paradox slot won't emulate on it.

Mode applies to HID Prox, Paradox and ioProx slots, and is saved on the CU straight away. stock: as stock firmware. self-trim: the new, stronger modulation drive, matched to the reader's clock (learned per slot). new drive only: the new drive without the matching, for comparison. + exact bits: HID Prox and Paradox bits at exactly the standard length; stock firmware makes some bits 4 % short. Fields seen: how many times this slot detected a reader arriving since the last clear. A reader that switches its field off and on again quickly can count once, so treat it as "the reader was seen", not an exact number of attempts. Reader vs CU: the clock difference self-trim measured and is correcting for; blank until it has learned a reader. Results are kept while the CU sleeps, and lost if the battery runs flat or the firmware is flashed.

Set up a test

Copies one HID Prox, Paradox or ioProx card into several slots, each with a different mode, so they can be compared at a reader by switching slots. The card's data only passes between the CU and this page's memory: it isn't shown, logged or stored, and nothing is sent anywhere else.

UseSlotNowMode
Connect to plan a test.

Only the slots' LF side is changed: an HF card in the same slot is kept. Each slot also gets an LF nickname naming its mode, e.g. "Paradox selftrim+x", so it's easy to tell them apart in other apps.

Backup and restore

A backup is a file with every slot's LF side: card type, card data, whether it's enabled, its nickname and its mode. Setting up a test downloads one first, automatically. Restore puts every slot's LF side back as it was in the file. HF cards are never changed. The file contains your cards' data: keep it somewhere private. Card types this firmware can't read (e.g. Indala) are listed in the file but can't be restored from it.

Trying it at a reader

  1. Load the card into one slot with your usual app or the CLI, then use Set up a test above with the recommended plan: stock, stock + exact bits, self-trim and self-trim + exact bits. That tells the two changes apart: self-trim helps a weak signal, exact bits help a reader that is strict about bit length. Clear results. Unplug.
  2. At the reader: present the CU on one slot several times, switch slots with the buttons, and do the same for each slot. Note which slot opened it and how quickly. Swap the order on another visit.
  3. Back here: Refresh, then Copy report and send it along with your notes. "Fields seen" shows whether the reader's field reached the CU; "Reader vs CU" shows the clock difference that was corrected.
