Firmware

Measuring needs the test firmware, which is Iceman master plus a command that reads the crystal-driven tick counter (source). Flash the test firmware with your own pm3 client, and flash your usual firmware back when you're done. Flashing the OS leaves the bootloader alone.

  • PM3 Easy and other generic boards: hw-ticks-a8471ac1-pm3generic-fullimage.elf
  • PM3 RDV4: hw-ticks-a8471ac1-pm3rdv4-fullimage.elf 
./client/proxmark3 /dev/tty.usbmodemXXXX --flash --image hw-ticks-a8471ac1-pm3generic-fullimage.elf

Run the command from your proxmark3 folder, with your PM3's port (/dev/ttyACM0 on Linux, COM5 or similar on Windows). To go back, run ./pm3-flash-fullimage there as usual.

Command line (Python script)

pm3_crystal.py performs the same measurement against NTP. The script also needs the test firmware, and the pm3 client must be closed. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/proxmark3/crystal/pm3_crystal.py
uv run pm3_crystal.py /dev/tty.usbmodemXXXX

uv installs pyserial automatically. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/proxmark3/crystal/pm3_crystal.py
pipx run pm3_crystal.py /dev/tty.usbmodemXXXX

pipx installs pyserial automatically. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/proxmark3/crystal/pm3_crystal.py
pip install pyserial
python3 pm3_crystal.py /dev/tty.usbmodemXXXX

On macOS or Linux (on Linux the port is usually /dev/ttyACM0). 

curl.exe -LO https://mfcarroll.github.io/rfid-test-tools/proxmark3/crystal/pm3_crystal.py
py -m pip install pyserial
py pm3_crystal.py COM5

In PowerShell or the Command Prompt.

For developers

The test firmware adds CMD_HW_TICKS (0x011B) to the PM3's protocol (branch feat/hw-ticks). The command reads the firmware's tick counter (TC0 and TC1 chained), which counts the master clock divided by 32. The PLL makes the 48 MHz master clock from the crystal. The count therefore runs at 1.5 MHz. The 125 kHz LF carrier also comes from the crystal and is off by the same ppm.

  • The command takes one byte. 0 starts the count from zero, 1 reads the count, and 2 stops the tick counter.
  • The reply is the count as a u32, little-endian. The count wraps every 47.7 minutes, and the page adds the wraps back.
  • Other firmware commands use the same tick counter. The page sends no other command during a run, and stops a run whose count jumps.
