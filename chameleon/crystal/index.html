Firmware

Measuring needs the test firmware: stock v2.3.0 plus a crystal tick counter (source). Chameleon Ultra only, not Lite. Flashing keeps your slots and saved cards. Flash stock v2.3.0 back when you're done. The FSK self-trim test firmware has the counter too: if your CU is on it, measure without flashing.

Command line (Python script)

hfxo_ntp.py performs the same measurement using NTP. It also needs the test firmware. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/chameleon/crystal/hfxo_ntp.py
uv run hfxo_ntp.py /dev/tty.usbmodemXXXX

uv installs pyserial automatically. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/chameleon/crystal/hfxo_ntp.py
pipx run hfxo_ntp.py /dev/tty.usbmodemXXXX

pipx installs pyserial automatically. 

curl -LO https://mfcarroll.github.io/rfid-test-tools/chameleon/crystal/hfxo_ntp.py
pip install pyserial
python3 hfxo_ntp.py /dev/tty.usbmodemXXXX

On macOS or Linux (on Linux the port is usually /dev/ttyACM0). 

curl.exe -LO https://mfcarroll.github.io/rfid-test-tools/chameleon/crystal/hfxo_ntp.py
py -m pip install pyserial
py hfxo_ntp.py COM5

In PowerShell or the Command Prompt.

For developers

The test firmware adds command 3125 to the CU's protocol, a tick counter for the crystal-driven 16 MHz clock (branch feat/hfxo-count).

  • It takes one byte: 0 starts the counter and holds the crystal on, 1 reads it, 2 stops it.
  • The reply is 20 bytes, big-endian: u64 ticks, u32 timer overflows, u32 raw timer value, u16 lapses (times the crystal was released while counting), u8 running, u8 crystal on now.
  • A run with any lapse is rejected: LF activity can release the crystal, so keep the CU away from readers while measuring.
